# 核心重构设计方案

## 项目背景

**当前 OpenMAIC 数据流：**
```
UserRequirements → SceneOutline → Scene → Stage
```

**目标项目数据流：**
```
教师需求 → 教学设计（结构化）→ PPT + Word 教案
```

---

## 1️⃣ 新核心数据模型

### A. TeachingRequest（教师输入）

```typescript
/**
 * 教师输入的教学需求
 * 替代原有的 UserRequirements
 */
interface TeachingRequest {
  // 基础信息
  subject: string;              // 学科，如"数学"、"物理"
  topic: string;                // 课题，如"二次函数的图像与性质"
  gradeLevel: string;           // 年级，如"初三"、"高一"
  duration: number;             // 课时（分钟）
  
  // 教学目标（可选，AI 可补充）
  objectives?: {
    knowledge?: string[];       // 知识目标
    skills?: string[];          // 能力目标
    attitude?: string[];        // 情感态度目标
  };
  
  // 风格与偏好
  stylePreferences?: {
    tone?: 'formal' | 'engaging' | 'interactive';
    visualStyle?: 'minimalist' | 'colorful' | 'professional';
    interactivityLevel?: 'low' | 'medium' | 'high';
  };
  
  // 知识库与资料
  useKnowledgeBase?: boolean;   // 是否使用 FastGPT 知识库
  uploadedMaterials?: string[]; // 上传的资料文件 ID
  
  // 其他
  additionalNotes?: string;     // 额外说明
  language: 'zh-CN' | 'en-US';  // 生成语言
}
```

### B. ReferenceMaterial（参考资料）

```typescript
/**
 * 统一的参考资料抽象
 * 支持 PDF、图片、PPT、Word 等多种格式
 */
interface ReferenceMaterial {
  id: string;                   // 资料唯一标识
  type: 'pdf' | 'image' | 'pptx' | 'docx' | 'txt' | 'other';
  name: string;                 // 原始文件名
  
  // 解析结果
  parsedText?: string;          // 提取的文本内容
  parsedImages?: ParsedImage[]; // 提取的图片
  
  // 元数据
  metadata: {
    uploadedAt: Date;
    size: number;               // 字节
    pageCount?: number;         // 页数（PDF/PPT）
    summary?: string;           // AI 生成的摘要
  };
  
  // 存储引用
  storageRef?: string;          // 文件存储路径或 ID
}

interface ParsedImage {
  id: string;                   // 图片 ID
  src: string;                  // base64 或 URL
  pageNumber?: number;          // 来源页码
  description?: string;         // AI 生成的描述
  width?: number;
  height?: number;
}
```

### C. TeachingContextBundle（三源融合结果）

```typescript
/**
 * 三源融合的上下文包
 * 这是喂给 LLM 生成教学设计的最终输入
 */
interface TeachingContextBundle {
  // 1. 教师意图（整理后）
  teacherIntent: {
    subject: string;
    topic: string;
    gradeLevel: string;
    duration: number;
    objectives: {
      knowledge: string[];
      skills: string[];
      attitude: string[];
    };

  };
  
  // 2. 资料解析结果
  extractedFromMaterials: {
    textContent: string;        // 合并的文本内容（截断到合理长度）
    availableImages: ParsedImage[];
    keyTopics: string[];        // 从资料中提取的关键主题
    suggestedStructure?: string; // 从 PPT 结构推断的建议
  };
  
  // 3. RAG 检索结果（FastGPT）
  retrievedKnowledge: {
    relevantChunks: string[];   // 检索到的知识片段
    references: string[];       // 引用来源
    confidence?: number;        // 检索置信度
  };
  
  // 4. 融合后的最终上下文
  mergedContext: string;        // 格式化后的完整上下文文本，直接喂给 LLM
}
```

## 2️⃣ 新旧结构映射关系

| 原结构 | 新结构 | 处理方式 | 说明 |
|--------|--------|----------|------|
| `UserRequirements` | `TeachingRequest` | **改造** | 增加学科、年级、课时等教学特定字段 |
| `SceneOutline` | `TeachingDesign`（初稿） | **替换** | Outline 阶段直接生成完整的 TeachingDesign 结构 |
| `Scene` | `TeachingSlide` | **替换** | Scene 的 slide 类型对应 TeachingSlide |

| `Scene.actions` | ~~删除~~ | **删除** | 教学设计不需要 Action 系统（spotlight、laser 等） |
| `Stage` | `Artifact` | **改造** | Stage 变为生成结果的容器，不再是运行时状态 |
| `Action` 系统 | ~~删除~~ | **删除** | 不需要实时交互，只需要静态文档生成 |
| `Quiz/Interactive/PBL` | ~~删除~~ | **删除** | 专注于传统课件+教案，暂不支持交互式内容 |

## 3️⃣ 复用分析

### ✅ 可以直接复用的结构

1. **`lib/types/slides.ts` 中的所有类型**
   - `Slide` - 作为 `TeachingSlide.canvas` 的类型
   - `PPTElement` 及其子类型（`PPTTextElement`, `PPTImageElement` 等）
   - `SlideBackground`, `SlideTheme` 等
   - **复用方式**：`TeachingSlide.canvas: Slide`

2. **`PPTElement` 作为底层表达**
   - `ContentBlock` 是高层语义描述
   - `PPTElement` 是底层渲染数据
   - 生成流程：`ContentBlock` → AI 生成 → `PPTElement`

3. **Speaker Notes 机制**
   - 原有的 `Slide.remark` 可以直接作为 `TeachingSlide.narration`
   - **映射**：`narration` → `canvas.remark`（导出 PPT 时）

### ⚠️ 需要适配的结构

1. **`lib/generation/outline-generator.ts`**
   - 当前生成 `SceneOutline[]`
   - 需要改为生成 `TeachingDesign`（完整结构）
   - **改造点**：Prompt 模板、解析逻辑

2. **`lib/generation/scene-generator.ts`**
   - 当前生成单个 `Scene`
   - 需要改为生成单个 `TeachingSlide`
   - **改造点**：生成逻辑、类型定义

3. **`lib/export/use-export-pptx.ts`**
   - 当前导出 `Scene[]` → PPTX
   - 需要改为 `TeachingDesign` → PPTX + DOCX
   - **改造点**：增加 Word 导出逻辑

### ❌ 不需要的结构（可删除）

1. **Action 系统**（`lib/types/action.ts`）
2. **Playback 引擎**（`lib/playback/engine.ts`）
3. **Multi-Agent 系统**（`lib/orchestration/*`）
4. **Quiz/Interactive/PBL 相关代码**

## 4️⃣ FastGPT 三源融合接入设计

### 生成流程

```
TeachingRequest + ReferenceMaterial[]
          ↓
    [资料解析模块]
          ↓
    extractedFromMaterials
          ↓
    [FastGPT RAG API]
          ↓
    retrievedKnowledge
          ↓
    [上下文融合模块]
          ↓
  TeachingContextBundle.mergedContext
          ↓
    [LLM 生成教学设计]
          ↓
    TeachingDesign
```

### 详细步骤

#### Step 1: 资料解析

```typescript
/**
 * 解析上传的参考资料
 */
async function parseMaterials(
  materials: ReferenceMaterial[]
): Promise<ExtractedMaterials> {
  const textContent: string[] = [];
  const images: ParsedImage[] = [];
  
  for (const material of materials) {
    // PDF 解析（复用现有逻辑）
    if (material.type === 'pdf') {
      const { text, images: pdfImages } = await parsePDF(material);
      textContent.push(text);
      images.push(...pdfImages);
    }
    
    // 图片解析（Vision API）
    if (material.type === 'image') {
      const description = await describeImage(material.src);
      images.push({
        id: material.id,
        src: material.src,
        description,
      });
    }
    
    // PPT/Word 解析（新增）
    if (material.type === 'pptx' || material.type === 'docx') {
      const parsed = await parseOfficeDocument(material);
      textContent.push(parsed.text);
      images.push(...parsed.images);
    }
  }
  
  return {
    textContent: textContent.join('\n\n'),
    availableImages: images,
    keyTopics: extractKeyTopics(textContent), // 使用 NLP 提取关键词
  };
}
```

#### Step 2: FastGPT RAG 调用

```typescript
/**
 * 调用 FastGPT 知识库检索
 */
async function retrieveFromKnowledgeBase(
  request: TeachingRequest,
  extractedMaterials: ExtractedMaterials
): Promise<RetrievedKnowledge> {
  // 构建查询文本
  const query = `
学科：${request.subject}
课题：${request.topic}
年级：${request.gradeLevel}

参考资料关键点：
${extractedMaterials.keyTopics.join('\n')}

请检索相关的教学资源、教学设计案例、学科知识点。
  `.trim();
  
  // 调用 FastGPT API
  const response = await fetch('https://fastgpt.example.com/api/v1/chat/completions', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${FASTGPT_API_KEY}`,
    },
    body: JSON.stringify({
      chatId: generateChatId(),
      stream: false,
      detail: true,
      messages: [
        {
          role: 'user',
          content: query,
        }
      ],
    }),
  });
  
  const data = await response.json();
  
  return {
    relevantChunks: data.responseData?.map(chunk => chunk.value) || [],
    references: data.responseData?.map(chunk => chunk.sourceName) || [],
    confidence: calculateConfidence(data),
  };
}
```

#### Step 3: 上下文融合

```typescript
/**
 * 融合三源信息，生成最终上下文
 */
function mergeContext(
  request: TeachingRequest,
  extracted: ExtractedMaterials,
  retrieved: RetrievedKnowledge
): TeachingContextBundle {
  // 整理教师意图
  const teacherIntent = {
    subject: request.subject,
    topic: request.topic,
    gradeLevel: request.gradeLevel,
    duration: request.duration,
    objectives: request.objectives || {
      knowledge: [],
      skills: [],
      attitude: [],
    },
    keyRequirements: extractRequirements(request.additionalNotes),
  };
  
  // 格式化融合后的上下文
  const mergedContext = `
# 教学设计任务

## 基本信息
- 学科：${teacherIntent.subject}
- 课题：${teacherIntent.topic}
- 年级：${teacherIntent.gradeLevel}
- 课时：${teacherIntent.duration} 分钟

## 教学目标
${formatObjectives(teacherIntent.objectives)}

## 参考资料内容
${extracted.textContent.substring(0, 3000)} // 截断到合理长度

## 可用图片资源
${extracted.availableImages.map(img => `- ${img.id}: ${img.description}`).join('\n')}

## 知识库检索结果
${retrieved.relevantChunks.join('\n\n')}

## 特殊要求
${teacherIntent.keyRequirements.join('\n')}

---

请基于以上信息，生成完整的教学设计，包括：
1. 教学目标（三维目标）
2. 教学重难点
3. 课件内容（每页的标题、要点、内容块）
4. 教学过程（导入、新授、巩固、小结等环节）
5. 作业布置
6. 板书设计
  `.trim();
  
  return {
    teacherIntent,
    extractedFromMaterials: extracted,
    retrievedKnowledge: retrieved,
    mergedContext,
  };
}
```

/**
 * 使用 LLM 生成教学设计
 */
async function generateTeachingDesign(
  bundle: TeachingContextBundle,
  model: LanguageModel
): Promise<TeachingDesign> {
  const systemPrompt = `
你是一位经验丰富的教学设计专家。
你的任务是根据教师需求和参考资料，生成结构化的教学设计。

输出格式必须是 JSON，包含以下字段：
- title: 课题名称
- objectives: { knowledge: [], skills: [], attitude: [] }
- keyPoints: 教学重点数组
- difficulties: 教学难点数组
- slides: 课件页面数组
- procedures: 教学过程数组
- homework: 作业布置数组
- boardDesign: 板书设计（文本）
  `.trim();
  
  const response = await generateText({
    model,
    system: systemPrompt,
    prompt: bundle.mergedContext,
  });
  
  const design = JSON.parse(response.text);
  
  return {
    id: nanoid(),
    ...design,
    createdAt: new Date(),
    updatedAt: new Date(),
    version: 1,
  };
}

## 🔟 风险与挑战

### 技术风险

1. **FastGPT API 稳定性**
   - 缓解：实现降级方案，RAG 失败时仍可生成

2. **Word 导出复杂度**
   - 缓解：先实现简单模板，逐步增强

3. **教学设计结构化难度**
   - 缓解：提供多轮对话，逐步细化

### 业务风险

1. **教学设计质量**
   - 缓解：引入人工审核环节，积累优质案例

2. **用户学习成本**
   - 缓解：提供向导式流程，内置示例

## 总结

本设计方案的核心思想是：

1. **最大化复用**：`Slide`、`PPTElement`、导出逻辑完全复用
2. **清晰分层**：`ContentBlock`（语义）→ `PPTElement`（渲染）
3. **三源融合**：教师需求 + 资料解析 + RAG 检索
4. **结构化输出**：`TeachingDesign` 作为中心数据模型
5. **渐进实施**：先 MVP，再增强，最后优化

这个方案既保留了 OpenMAIC 的优秀架构，又满足了教学设计的特殊需求。
